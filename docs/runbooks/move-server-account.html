Runbook · Render · account move

Move a server to a new account

Create the server in the new account, point the frontend at it, and only then delete the old one. Tick each step as you go; progress is saved in this browser.

0 of 0 done
01

Prepare

Name, account, live URL, branch, plan and region. You will need the URL and branch in the next phases.

What to note
  • Service name and its .onrender.com URL
  • Account it is in now, and the account you are moving it to
  • Branch it deploys and whether auto-deploy is on

Open the server, go to Environment variables and press ▣ Snapshot. This is your backup of every variable.

Gate: snapshot listed under “Encrypted snapshots”

The new account needs access to the GitHub repo and a free-plan slot. Stashr reads this from the GitHub connection on the Create & deploy page.

Search the variables of your frontend services for the old URL. Note each service name.

How to find them
  • Use Deployments → Copy env or the URL-replace tool, which lists references across services
  • Check the repo too: a URL hard-coded in code needs a commit (phase 04)
02

Build the new server

Open Create & deploy, choose Use an existing repository, pick the same repo and branch, and set Render account to the new one. Keep the same runtime and build commands.

Gate: deploy reaches Live (Logs panel shows the deploy)

On the new server, press Copy env and choose the old server. Read the preview: names only, nothing is written until you confirm.

What to check in the preview
  • “new” count equals the old variable count, minus any that differ on purpose
  • Keep Then deploy the latest commit ticked

Open the new URL in a browser and check its health route. The Overview tab runs an endpoint health check.

Gate: health check is green and logs show no startup errors
03

Point the frontend at it

Use the URL-replace tool: old URL in, new URL out, for each frontend service from step 04. Review the list before applying.

Saving variables on the Render server page deploys the latest commit automatically. Check the deploy reaches Live.

Open the frontend, sign in and use one feature that calls the server. Check the new server’s logs show the request.

Gate: a real request reaches the NEW server, not the old one
04

Ship the code

Skip this if step 08 changed everything. If a URL is written in code, change it, commit to main and push. This goes live on the next auto-deploy.

In the project page, open Stashr ⇄ Render variables and link the new server with Link service. The new server becomes the project’s main server, so Deployments and sync use it from then on.

05

Retire the old server

Leave the old server up while you watch the new one. Nothing is deleted yet.

Only now. Render asks you to type the service name. This cannot be undone, except from the snapshot in step 02.

Gate: steps 07, 10 and 13 are all ticked

Status Running, branch correct, auto-deploy on if it was on before, and the Servers URL list shows the new URL.

Stop and roll back if

  • The new server does not reach Live, or its health check fails. Do not continue. The old server is still running.
  • The frontend shows errors after the URL change. Put the old URL back with the same replace tool, then redeploy.
  • A variable is missing on the new server. Copy it again from the snapshot before going on.
